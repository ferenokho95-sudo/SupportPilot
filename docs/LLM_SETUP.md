# Подключение внешней модели

Локальный режим полностью работоспособен без ключа. Для генерации через API нужны собственный ключ и доступная модель совместимого провайдера.

Windows PowerShell, перед запуском приложения:

```powershell
$env:LLM_API_KEY="ваш_ключ"
$env:LLM_MODEL="id_доступной_модели"
$env:LLM_BASE_URL="https://api.openai.com/v1"
.venv\Scripts\python.exe app.py serve
```

`LLM_BASE_URL` замените на HTTPS-адрес совместимого провайдера, включая `/v1`, если он нужен. Клиент обращается к `/chat/completions`, передаёт model, messages и temperature=0.2. Модель должна поддерживать эти поля и возвращать `choices[0].message.content`; формат `usage` — prompt_tokens/completion_tokens. Некоторые модели не поддерживают temperature или этот endpoint — для них адаптируйте common.py по документации провайдера.

SupportPilot: выберите LLM в интерфейсе. Необязательные тарифы:

```powershell
$env:LLM_INPUT_USD_PER_MILLION="входной_тариф_числом"
$env:LLM_OUTPUT_USD_PER_MILLION="выходной_тариф_числом"
```

ExperimentLab: выберите API, укажите модели A/B (или используйте одну LLM_MODEL для двух промптов). Для чистого сравнения моделей выберите одинаковые промпты A/B; для сравнения промптов используйте одну модель. Для каждой модели укажите тарифы в соответствующих полях интерфейса. Пустые тарифы означают неизвестную стоимость. Ключ не вводится в браузере и не включается в репозиторий.

Формула: `(prompt_tokens * input_price + completion_tokens * output_price) / 1_000_000`. Это оценка по указанному тарифу, без налогов, скидок, кэша и других специальных правил тарификации.

Без usage или одного из тарифов стоимость = null. Ошибка API не превращается в успешный локальный ответ. При невалидных ссылках или JSON ответ отклоняется. Передайте только данные, которые разрешено отправлять выбранному провайдеру.

Внешние платные API в комплектной проверке не использовались. Есть локальный HTTP-тест контракта клиента, который не подтверждает доступ к реальному провайдеру.
